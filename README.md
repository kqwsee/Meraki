# Meraki — обучение с ИИ-наставником

Веб-приложение для изучения навыков и знаний с ИИ-наставником. Автор загружает курс и материалы (учебник, задачи), ИИ строит **граф знаний**, и каждая вершина графа проходится в 4 этапа:

1. **Пролог.** Непринуждённая беседа около темы: ИИ выясняет, что ученик знает, задаёт пре-вопросы, ищет заблуждения.
2. **Лекция.** Объяснение порциями под уровень и склад ума ученика, вопросы на понимание, в конце выходной билет (пересказ своими словами).
3. **Практика.** Холст (Excalidraw), виртуальные файлы, редактор кода и панель инструментов под предметную область, с поиском по всем инструментам. Задания идут по схеме «разбор → измени → создай» (PRIMM / Блум), подсказки — лестницей. Вставки и скорость ввода **записываются, но не наказываются**: они смещают экзамен к тем же понятиям.
4. **Экзамен.** То же рабочее пространство, но без помощника, подсказок и с таймером. Если система заподозрила несамостоятельность (вставка, ввод в стиле переписывания, уход со вкладки), после экзамена идёт «защита решения» — вопросы по этим фрагментам.

После каждой темы ИИ обновляет **профиль** ученика (таланты, склад ума, сильные стороны, профиль ввода, калибровка уверенности) и **перестраивает личный маршрут** по графу: меняет порядок, назначает режим «ускоренно» или «углублённо», при необходимости добавляет «мостовую» тему. Долговременная память хранится в [MemPalace](https://github.com/mempalace/mempalace): в неё пишутся итоги тем и сессий, а читается она в начале этапов.

Педагогическое обоснование: [docs/PEDAGOGY.md](docs/PEDAGOGY.md). Анализ ввода и этика: [docs/TYPING_ANALYTICS.md](docs/TYPING_ANALYTICS.md).

## Архитектура

```
frontend/  React 18 + Vite + TypeScript
  pages/         вход, главная, редактор курса, граф курса, этапы темы, профиль, повторение
  workspace/     холст, файлы, CodeMirror, интерпретаторы (Pyodide, JS-воркер, sql.js), задания и экзамен
  tools/         18 инструментов (калькулятор, Python/JS/SQL, схемы DC с MNA-решателем, ДНК, Пеннет, Менделеев…)
  telemetry/     запись действий и динамики ввода (сегменты, паузы ≥2 с, правки, вставки и их источник)

backend/   FastAPI + SQLite (SQLAlchemy, FTS5)
  llm/           провайдеры: claude_cli (подписка Claude через `claude -p`) | openai (любой OpenAI-совместимый API)
  memory.py      клиент MemPalace (MCP по stdio) + запасное хранилище в SQLite
  prompts.py     промпты всех этапов и JSON-схемы
  services/      материалы, граф, этапы, самостоятельность, маршрут, профиль, сессии, интервальное повторение
```

## Запуск (Windows / macOS / Linux)

Нужны Python 3.13+ с [uv](https://docs.astral.sh/uv/), Node 20+ и Claude Code, в котором вы залогинены через подписку (`claude`).

```bash
cd backend
uv sync
cp .env.example .env   # задайте SECRET_KEY
uv run uvicorn app.main:app --port 8000
```

```bash
cd frontend
npm install
npm run dev            # http://localhost:5173, /api проксируется на :8000
```

Первая запись в MemPalace скачивает локальную модель эмбеддингов (один раз, около 2 минут). Первый запуск Python в браузере загружает Pyodide (около 10 с).

Тестовые учётки для локальной разработки: `backend/scripts/dev_seed.py`.

### Сменить нейросеть

В `backend/.env`:

```env
LLM_PROVIDER=openai
OPENAI_BASE_URL=https://api.openai.com/v1      # или OpenRouter, Ollama (http://localhost:11434/v1), LM Studio
OPENAI_API_KEY=sk-...
LLM_MODEL_FAST=gpt-4o-mini                      # диалоги
LLM_MODEL_SMART=gpt-4o                          # граф курса, генерация и проверка заданий
```

По умолчанию стоит `claude_cli`: модель `haiku` для диалогов и `sonnet` для структурирования курса и заданий. Вызовы идут через вашу подписку Claude, без API-ключа. Это вариант для личной разработки: для продакшена с другими пользователями переключитесь на API-ключ.

### Сборка в один сервер

`npm run build` во `frontend/`. После этого бэкенд сам отдаёт `frontend/dist` на `:8000`.

## Ограничения MVP

- Код выполняется только в браузере: Python (Pyodide), JavaScript, SQL. Docker-песочница для других языков пока не сделана.
- Схема БД создаётся через `create_all`, миграций (Alembic) пока нет: при изменении моделей dev-базу (`backend/data/meraki.db`) нужно удалить.
- Фоновые задачи ИИ (генерация заданий, проверка экзамена) хранятся в памяти процесса. Для нескольких воркеров нужна очередь.
- Конструктор схем решает только линейные цепи постоянного тока.
